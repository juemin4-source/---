## 启动

需要 Node.js 22.12+ 或 24 LTS。当前机器已安装依赖。

```powershell
cd 'G:\杂活\决明工作室\黑日计划'
npm install
npm run dev
```

在浏览器打开终端显示的地址（默认 http://127.0.0.1:5173），点击「开始第一次出行」。桌面键盘 + 鼠标，建议 1280×720 以上。窗口自动保持 16:9；第一次点击解锁合成音效。离开浏览器窗口会自动暂停。

```sh
npm test         # 机制测试
npm run build   # TypeScript 检查 + 生产构建
npm run preview # 本地运行 dist 构建
```

`dist/` 是可静态部署的完整产物。Phaser 引擎会产生一个约 1.2 MB（gzip 332 KB）的独立包，因此 Vite 会提示大块体积；这不影响运行。源代码与引擎分包。

## 操作

| 输入 | 作用 |
| --- | --- |
| A / D | 左右移动，空中可调整 |
| Space | 跳跃；短按低跳，长按高跳 |
| S | 穿过上层单向平台下落；实体地面保持碰撞 |
| H | 使用医疗针，每趟初始 2 支，各恢复最多 45 生命 |
| Shift | 短冲刺，约 0.68 秒冷却，短暂无敌 |
| 鼠标 / 左键 | 360° 瞄准 / 按住连续射击，无限弹药 |
| F | 朝瞄准方向近距离震脱；完整零件通常需要两次 |
| 右键 | 朝瞄准方向发射定相束，最远 360 像素 |
| E | 探索模式：一键接入最近器官；旧测试场：搬运 |
| G / V | 探索模式：部署选中器官 / 原物理搬运 |
| 1 / 2 / 3 / 4 | 选择随身器官；满链路时 E 替换选中项 |
| Q / 滚轮 | 旋转手持零件，或附近鼠标指向的零件 |
| W | 搜索 / 通行；气闸长按安全撤离 |
| Tab | 分支地图，打开时暂停 |
| R | 探索模式：紧急回收确认，保留约 30%；旧测试场：重试房间 |
| Esc | 暂停 / 继续 |
| M | 静音切换 |
| F1 | 开关调试面板 |

推进囊和牵引腕以 45° 步进旋转；盾板为 90°。定相只稳定工作状态和朝向，不锁死位置。鼠标移动改变手持位置，旋转键改变喷口/牵引方向。被地形遮挡的放置会被拒绝，需抬高鼠标或移开。

探索模式接入推进囊后，空中再按 Space 可喷跳，落地充能；也可按 G 放下，继续使用原有物理喷流。探索模式中，资源和三项升级保存在当前浏览器；刷新或重开未完成的出行按中断救援处理，保留约 30% 资源。暂停可用于暂时离开。

## 已实现

- 快速起停、120 Hz 固定模拟步长、土狼时间、跳跃缓冲、变高度跳跃、空中修正、冲刺、边移动边射击。
- 独立核心和模块碰撞盒。射击损伤耐久；F 损伤连接强度，完整拆下的模块保留功能。旧测试场打爆核心会损毁仍连接的器官；探索模式击杀会保留一件可用休眠器官（精英两件），主动震脱可提前夺取能力并使宿主短暂失衡。
- 推进囊：失控喷气、反冲；定相后持续方向喷流，可以升空、推敌、推盾。
- 炮腕：失控乱射且可误伤敌人；定相后自动瞄准附近敌人。
- 甲壳盾：安装状态提供方向防御；落地有重量；定相后挡弹、阻挡敌人、可被喷流推动；高速撞击造成伤害。
- 牵引腕：失控抽动；定相后抓取前方扇区内的模块或敌人并施加拉力。
- 最多三个定相模块，第四个解除最早的一个；手持模块仍占用定相数量。
- 爬行、浮游、回收三种敌人，以及大型甲壳聚合体。浮游失去推进器后坠落；失去炮腕后不再开火；回收星骸优先拉走场上的零件。
- 五个短房间、波次、清场出口、高台、通关画面、死亡重试。进房恢复生命，可以携带手中的一个零件进入下一房间；重试还原入房时携带的零件。
- 第二房间缺失所有可用推进器后会补入一只推进星骸，避免永久卡关。
- 枪口闪光、弹道、受击闪白、裂纹、红色连接点、震脱碎片、定相光束光环、冲刺残影、屏幕震动，以及 Web Audio 合成音效。
- F1 调试：生成四种模块、四种敌人、清敌、无敌、碰撞盒、跳房间。

  Player.ts           移动与冲刺
  Enemy.ts            敌人实体、器官安装
  EnemySystems.ts     三种敌人和精英的行为
  EnemyModule.ts      零件耐久、连接强度、状态
  ModuleSystems.ts    喷流、炮击、牵引、碰撞与盾板冲撞
  PhysicsHelpers.ts   AABB 物理、扫掠弹道碰撞
  Projectile.ts       弹丸数据
  Levels.ts           五房间配置
  Renderer.ts         全程序生成的游戏画面
  Effects.ts          特效事件与合成音效
  DebugTools.ts       调试面板
  style.css           界面
tests/                机制与关卡自动测试

四种模块共用简单实体，由 `ModuleSystems.ts` 按类型执行行为，未引入 ECS 或复杂继承框架。

## 简化与边界

- 物理是有质量、重力、推拉与 AABB 碰撞的游戏化模拟，不是真实刚体或任意角度多边形碰撞。盾板仅支持横/竖放置。
- 回收星骸会拖走零件，但不会重新安装；牵引固定锚点荡跃尚未实现。
- 稳定炮腕采用自动炮台方案；旋转不会覆盖其自动索敌。没有重武器模式。
- 跨房仅带走手持的一个零件，其余留在原房。不是背包或存档系统。
- 可用的落地零件对普通枪弹作了保护，避免定相前意外误毁；未稳定盾板仍会缓慢受损。附着器官可被射毁。
- 5–10 分钟是探索目标，并未通过多人新手测试校准。熟练玩家直接打核心会明显更快。
- 没有正式角色美术、剧情、持久化、移动端或手柄支持。

## 本轮试玩结论

已做真实浏览器键鼠操作检查，并在受控场景中实测推进升空和盾板冲撞；不是已经完成大样本体验测试。详细结果见 `VALIDATION.md`。

目前最大的问题是**战斗节奏与摆放零件的时间窗口冲突**：拆件很快，但在敌人追击时，拿起、改变喷口、放下需要注意地面位置，玩家容易退回直接射核心。盾板确实可以被喷流加速杀敌；不过让新玩家自己安排出这个场面，还需要改善空间和敌人节奏。

下一轮最值得改的三件事：

1. 在成功震脱后给敌人更清晰的短暂失衡窗口，并在拿着模块时画放置轮廓，提高战斗中摆放成功率。
2. 用更明显的喷流边界、受力预览和第一次组合反馈，让玩家更容易读懂零件之间的因果关系。
3. 找 3–5 名未读说明的玩家试玩，记录第一次完整拆件、定相、高台通过、盾板冲撞的时间，再调整伤害、敌人追击和房间长度。
